检查 `dabby-client.ts` 的 `getQrCode()` 方法，修复 API 调用问题。

## 问题2：用户回复"确认"就执行了（核心问题）

### 当前错误流程

1. 用户发送敏感命令 → 拦截 → block: true
2. 机器人发送验证链接
3. 用户回复"确认" → 这是普通聊天消息，不触发敏感检查
4. Agent 可能会调用工具执行用户请求的操作

### 根本原因

`before_tool_call` 只拦截**工具调用**，不拦截聊天消息。用户回复"确认"会被 LLM 解析后可能触发其他工具。

### 修复方案

**修改 `src/auth-manager.ts`：**

- 在认证成功后，设置用户为已验证状态，并立即自动重新发送原始命令
- 自动重发的命令会再次触发 `before_tool_call`，但用户已验证，所以允许执行

**修改 `src/server.ts`：**

- 认证成功回调中，立即标记用户为已验证（已做）
- 确保 `markUserVerified` 在 `verifySession` 返回成功时立即调用

**修改 `src/providers/qr-code.ts`：**

- 更新成功提示文案，说明系统会自动执行命令

### 修复后流程

1. 用户发送敏感命令 → 拦截 → block: true
2. 机器人发送验证链接
3. 用户扫码认证成功
4. 系统自动将原始命令发送回同一会话
5. 重新发送的命令触发 `before_tool_call`
6. 检查用户已验证 → 允许执行
7. 命令成功执行

### 用户无需回复"确认"

用户只需扫码认证，系统会自动处理所有后续步骤。
