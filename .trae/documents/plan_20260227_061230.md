## 实现计划：区分首次对话认证和敏感操作二次认证

### 1. 扩展配置 ([config.ts](g:\www-xxk\openclaw\extensions\mfa-auth\src\config.ts))

- 添加 `persistAuthStateDir`：持久化目录（默认 `~/.openclaw/mfa-auth/`）
- 添加 `requireAuthOnFirstMessage`：是否首次对话需要认证（默认 `true`）
- 添加 `firstMessageAuthDuration`：首次认证有效期（默认 24 小时）
- 保留 `verificationDuration`：敏感操作认证有效期（当前 2 分钟）

### 2. 扩展类型定义 ([types.ts](g:\www-xxk\openclaw\extensions\mfa-auth\src\types.ts))

- 在 `MfaConfig` 中添加新配置项类型
- 在 `PendingAuthContext` 中添加 `triggerType: "first_message" | "sensitive_operation"` 字段

### 3. 扩展 AuthManager 类 ([auth-manager.ts](g:\www-xxk\openclaw\extensions\mfa-auth\src\auth-manager.ts))

**分离两种认证状态管理**：

- `verifiedUsers` → `verifiedForSensitiveOps`：敏感操作认证（2分钟）
- 新增 `verifiedForFirstMessage`：首次对话认证（24小时，持久化）

**新增方法**：

- `persistFirstMessageAuth(userId: string)`：持久化首次认证状态
- `loadPersistedFirstMessageAuth()`：启动时加载持久化状态
- `isUserVerifiedForFirstMessage(userId: string)`：检查首次认证状态
- `isUserVerifiedForSensitiveOps(userId: string)`：检查敏感操作认证状态（原 `isUserVerified`）
- `clearFirstMessageAuth(userId: string)`：清除首次认证状态（用于 `/reauth`）

**修改现有方法**：

- `verifySession()`：根据 `triggerType` 更新不同的认证状态
- `cleanup()`：清理两种认证的过期状态
- 在构造函数中调用 `loadPersistedFirstMessageAuth()`

### 4. 修改主插件注册 ([index.ts](g:\www-xxk\openclaw\extensions\mfa-auth\index.ts))

**添加 message_received 钩子**：

- 检查 `isUserVerifiedForFirstMessage(userId)`
- 如果未认证且启用首次认证配置：
  - 生成认证会话（`triggerType: "first_message"`）
  - 发送认证链接到用户
  - 返回阻止继续处理的消息

**修改 before_tool_call 钩子**：

- 保持敏感词检测逻辑
- 使用 `isUserVerifiedForSensitiveOps(userId)` 检查敏感操作认证
- 生成会话时设置 `triggerType: "sensitive_operation"`

**注册 /reauth 命令**：

- 使用 `api.registerCommand()` 注册 `/reauth` 命令
- 清除用户当前的首次认证状态
- 触发新的首次认证流程

**修改 notifyCallback**：

- 根据 `triggerType` 提供不同提示：
  - `first_message`："🎉 首次认证成功！您可以继续与 AI 对话。"
  - `sensitive_operation`："✅ 敏感操作验证成功！请重新发送命令或回复'确认'以执行。"
- 首次认证成功时调用 `persistFirstMessageAuth(userId)`

### 5. 持久化存储格式

- 文件路径：`~/.openclaw/mfa-auth/first-message-auth.json`
- 格式：`{ "userId": { "verifiedAt": 1234567890 } }`

### 6. 测试场景

- **首次对话**：新用户首次对话 → 触发认证 → 成功后可对话
- **敏感操作**：已认证用户触发敏感词 → 触发2分钟认证 → 成功后执行命令
- **主动重新认证**：用户发送 `/reauth` → 重新触发首次认证 → 刷新24小时计时
- **持久化验证**：重启网关后，已首次认证的用户状态保持
- **过期处理**：24小时后首次认证过期，需要重新认证
